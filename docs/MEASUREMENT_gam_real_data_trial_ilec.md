## Findings

**1. Full-granularity cells are memory-limited on this host.** All six failed cells are `full`.
Polaris finished in each. The containerised `mgcv` fit did not. T2 full was re-run with 19.26 GiB
of Docker memory and exited with code 137 with `OOMKilled=true`, so the operating system killed it.
The other five failed cells have the same or similar row counts (about 2.8–3.0 million). They are
recorded as failed, and the cause is the host memory limit, not the model. A full-granularity fit
needs more memory than this host can give Docker.

**2. The S1 data rule refuses the formula.** S1 uses a binomial cloglog response, `deaths / exposure`,
which must be a proportion. The trial refuses S1 when any aggregated cell has more deaths than
exposure. The existing data rules check only zero-exposure cells, so this condition is not caught
earlier. Its extent has not been measured in this trial. This is a finding about the extract.

**3. Two gates are missed.** S2 mid and S3 mid miss the eta gate (max |Δη| 0.037 and 0.047, against
0.02). T3b mid misses the se gate (relative se difference 0.022, against 0.02). Gates were not relaxed.

**4. Polaris exceeds the 600 s ceiling on six cells:** T2 full (648 s), S2 full (807 s), T3b mid
(841 s), T3a full (1220 s), S3 full (1871 s), T3b full (2117 s).

**5. `n_coef_diff` is non-zero for S2, S3 and T3a.** The two designs have different widths for those
formulas. This is the design-width mechanism described in ADR-259, and it is reported as found.

**6. Score gaps are mostly negative.** A negative gap means the outer search stopped slightly short
of `mgcv`'s smoothing parameters (mechanism class iii). S3 mid is the largest, at −0.29. The two positive
gaps are T1 mid (+0.00054) and T2 mid (+0.0058).

**7. No timing ratio is comparable.** Every cell is marked `ratio_comparable = False`. The ratios
(about 0.07–0.28) are reported as recorded and are not like-for-like. The runbook's bam trigger
(ratio above 1.5 at full, comparable only) does not fire.

**8. Warnings in the score-gap path.** `numpy.linalg.slogdet` produced divide-by-zero, overflow and
invalid-value warnings while evaluating the REML score at `mgcv`'s smoothing parameters (see
`gam_reml.py:409`). The final Polaris fit for T1 coarse is unaffected: its score is finite and its
EDF matches `mgcv` to about 1e-4. The warnings have not been checked against each cell's score gap,
so the score gaps should be read with that caveat.

## Run history

The result file records one machine setting, 15.66 GB, for 23 of 24 cells. Cell file timestamps
show they were all written between 2026-10-12 09:37 and 2026-10-13 01:43, which predates the
19.26 GiB setting. T2 full was re-run at 19.26 GiB and is the only exception. Earlier runs at 7.65 GB
had produced different failures and were superseded by these cell files.

- Measure the extent of the S1 data gap, using counts only.

  oracle used by these gates.
