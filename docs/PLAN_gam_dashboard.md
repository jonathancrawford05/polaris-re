## 2. Definition of done
A maintainer can, in the existing experience-improvement page and with data they load themselves: choose a formula from the verified subset, choose `gam` or `bam` (default by size, §3), read the runtime and memory warning BEFORE the run, run the fit, and see the fitted effects, `edf`, convergence flags and `summary()`; an unsupported formula shows the refusal message by name; nothing the page shows feeds pricing. All tests run without real data.

## 4. The slices (each ships a user-visible capability; no splitting without a maintainer comment)
- **D1 — fit and display, read-only. [IMPLEMENTED 2026-10-22, ADR-262]** A "GAM (HGAM fitter)" section on the existing page: formula input with the verified-subset help text and refusal messages, family choice, engine choice with the §3 default, the pre-run warning from a measured cost model, the fit, the effects/edf/convergence/`summary()` display. Comparison/evidence: the page's numbers are `polaris_re.gam`'s (already INDEPENDENT-verified); D1's own checks are MEASUREMENT (own criterion): the cost model is validated against the committed R2/R3 timings (predicted vs measured, reported, with the tolerance derived before the first run), and a UI test asserts the warning text for each engine x size cell. **Release condition:** none; first slice.
- **D2 — [IMPLEMENTED 2026-11-07, ADR-263, all six checkpoints] HGAM-driven effects and improvement surface in the page's views (planned 2026-11-07 with the maintainer; ADR-263 PROPOSED; release: the maintainer's go, given in conversation 2026-11-07, to be confirmed on the D2 PR).** ONE slice with ordered checkpoints (no further split without a maintainer comment). Maintainer decisions (2026-11-07): (1) both the fitted effects AND the improvement surface `MI_x(y)`; (2) the page's views are driven by the HGAM; the old `ExperienceGAM`/`TensorMIModel` code stays in the repo, untouched, because pricing-adjacent paths use it (CLI, `improvement_version_id`, ADR-148), and its retirement is NOT a D2 task and not a priority; (3) no pricing link; (4) `q_base` is an OPTIONAL offset (when present the A/E multiplier keeps its old meaning, otherwise `log_exposure`); (5) true partial effects, `gam` and `bam` as the only engine choice (the 300k default and warnings stand); (6) no old-vs-new comparison (the old model is not a reference for correctness); correctness is **truth recovery** on data with a known answer; (7) thoroughness over speed; (8) the Bayesian projection fan stays on the old model, labelled so, until an HGAM Bayesian feature exists (eventually wanted, its own plan, not D2).
  **Checkpoints, in order, each with its own tests before the next begins:**
  1. **Definition and claim sentences (no code).** `MI_x(y) = 1 - exp(eta(x,y) - eta(x,y-1))`, the SAME definition the old model documents (`TensorMIModel.improvement_surface`), with every non-calendar term and the offset cancelling. Band: delta method on the linear contrast, `Var(d) = D Vp D^T` where `D = X(x,y) - X(x,y-1)` from `predict_design` and `Vp = fit.vcov()`; never independent per-point standard errors (the covariance between the two points is the whole point). Claim sentence for the truth check (a comparison against a CLOSED FORM: INDEPENDENT producers, the generating formula and the fit, NOT `mgcv` parity; declare it with a `VerificationClaim`; corrected in review round 2): "the HGAM fit recovers the improvement baked into the data; the truth is the generating formula; compared on MI at each (age, year) and on band coverage."
  2. **Partial effects.** For each smooth term, its centred contribution on a grid with a band from the term's block of `Vp` (stated reference: other terms excluded, the standard `plot.gam` convention); factor and `by` terms included; `ti` shown as a surface. Replaces the link profiles of D1.
  3. **The improvement surface.** The contrast above over an age x year grid from a model with `ti(attained_age, calendar_year)` plus main smooths (`cr`); refused with the standard message if the formula has no calendar-year smooth. `gam` and `bam` both; for `bam` the band uses its `Vp` (no `Vc`).
  4. **Truth-recovery tests (tolerance derived and written BEFORE the first run).** (a) The built-in sample (flat 1.5%/yr, noise-free): `MI` equals 0.015 to within the fit's own band at every cell. (b) A seeded Poisson draw with an AGE-VARYING known improvement (written in the test as a closed form): the band must cover the truth at a stated rate and the max |MI - truth| must lie under a bound derived from the draw's own standard errors. (c) Both repeated across seeds so one lucky draw cannot pass. A miss is reported as a result, never closed by widening the tolerance.
  5. **Page wiring.** The page shows the HGAM effects and surface with the engine labelled; the old views no longer render by default (kept behind a clearly labelled "legacy model" expander so nothing is silently removed); the pre-run warning and the explicit Run button stay; refusals shown by name. AppTests for each state.
  6. **Honesty checks.** Every number on the page labelled with its engine; the surface labelled "MEASUREMENT: not an actuarial recommendation, not fed to pricing"; goldens byte-identical.
  **Definition of done:** the maintainer can load their data, run the HGAM, and read effects and an `MI_x(y)` surface with bands and a download, with truth-recovery tests passing at their pre-registered tolerances and the legacy views reachable. **Open design risks:** `ti` surfaces on sparse age x year cells (band width at the edges); whether `bam`'s `Vp` is adequate for a contrast (ADR-260 amendment 17 fixed an observed-vs-Fisher weight defect for cloglog only); the `slogdet` warnings on the `gam` path should be examined before the surface is trusted (PRODUCT_DIRECTION 2026-11-07 follow-up).
- **D3 — other surfaces** (CLI, MCP, API). **Release condition:** the maintainer's written go after D2; Anchor 7 stays until then.

## 5. Rules that keep this epic from spiralling
1. One slice per session; D2 and D3 are not started without their release condition. 2. No solver work, no new start strategy (the outer search is closed; Newton is the default). 3. No new `mgcv` constructs: a formula the verified subset refuses stays refused, with its message. 4. A number the page shows without a second producer is labelled MEASUREMENT, not parity. 5. The cost model is measured, labelled with the machine it was measured on, and refuses to extrapolate beyond the measured range without saying so. 6. Real data never enters the repo or the cloud. 7. Existing pages' behaviour and the goldens (`tests/qa/golden_outputs/`) stay unchanged; the new section is additive. 8. Questions go to the maintainer the session they arise (PR body + CONTINUATION), with a recommended answer.

## 6. Risks, in the order they are likely to bite
1. The page's fit machinery today is the older experience GAM; adding a second engine to one page without confusing which numbers are which (label every number with its engine). 2. The cost model is built from one maintainer machine's profile; it must say so and widen its stated uncertainty off that machine. 3. Streamlit rerun semantics: a multi-minute fit must not re-execute on each widget change (cache by a fit signature, as `_cached_fit_models` does). 4. Memory: a `gam` request near the ceiling can take the dashboard process down; the warning is mandatory and the run is explicit, not automatic.
